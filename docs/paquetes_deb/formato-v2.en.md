# Module `.deb` format v2

A Kairos `.deb` is a regular Debian `.deb` (`dpkg-deb -b`) whose **control area** (`DEBIAN/`) carries, besides
`control` and `postinst`, two mandatory files.

## `DEBIAN/manifest.json`

Generated by `moduledeb pack` from `<id>.sh --describe-files`, which adds the fields marked with ★.

| Field | Meaning |
|---|---|
| `id` | catalog module id (`claude`, `opencode`, ...). Required. |
| `package_name`, `variant`, `version_registry_key` | package name, installed variant (`native`, `gpu`, ...), registry key the version comes from |
| `files[]` | **exact** paths the package installs: `{path, required, note}` |
| `file_globs[]` | trees/patterns: `{pattern, required, note}` (`dir/**` = the whole tree, `dir/lib*.so` = one directory) |
| `dependencies[]` | **requirements**: `{id, check_cmd, install_hint}` + ★`kind` + ★`packages[]` (see below) |
| `verify_cmd` | command that tells whether the module is already correctly installed |
| `patch_cmd` | lightweight repair after copying (e.g. `patchelf` of the interpreter) |
| `not_covered[]` | honest limitations: what the package does NOT include |
| ★`kairos_package` | `true` — Kairos package marker |
| ★`schema` | `2`. Anything below 2 is rejected |
| ★`pack_date` | creation date |
| ★`checksums_file` | `"SHA256SUMS.txt"` |

### Requirements (`dependencies[]`)

Each requirement has a `kind` that decides how it is checked and resolved **without running anything foreign
ahead of time**:

| `kind` | What it is | How it is checked before confirming | How it is resolved if missing |
|---|---|---|---|
| `package` | only `pkg install -y <names>` (the installer infers it when packing if `install_hint` is exactly that) | `dpkg -s <each package>` — no `eval` | `pkg install -y` with validated names (`^[A-Za-z0-9+._-]+$`), no shell |
| `addon` | Kairos add-on (Tor, Syncthing, Restic, 7z...) — **reserved**, no module declares it yet | — | the add-on is installed with its `AddonEngine` |
| `module` | another catalog module — **reserved** | — | normal module installation |
| `other` | any other command | cannot be checked (stays `unknown`) | runs `install_hint` **only after** confirmation or a hash-verified origin |

`check_cmd` is only evaluated in the `verify` phase, after the package has passed inspection.

## `DEBIAN/SHA256SUMS.txt`

Standard `sha256sum` format (can be checked by hand with `sha256sum -c`):

```
# Kairos package checksums (sha256). Formato: <sha256>  <ruta relativa a />. '#' = comentario.
bc58dcd7...974d  DEBIAN/manifest.json
f4682aea...3b86  data/data/com.termux/files/home/.local/bin/claude
79343690...036c  data/data/com.termux/files/home/.local/share/claude-code/claude
# symlink data/data/.../lib/libfoo.so -> libfoo.so.1
```

- First data line: the hash of `manifest.json`. If it does not match, the manifest was tampered with → rejection.
- One line per **regular file** of the payload (paths relative to `/`).
- **Symbolic links** are written as a comment `# symlink <path> -> <target>`.
- The set must be **exactly** the package's: an extra file, a missing one or one with a different hash → rejection.

## Allowed paths

Every payload file must satisfy, besides being listed in the `.txt`:

- Its absolute path (`/` + relative path) is under `$HOME` (`/data/data/com.termux/files/home`) or `$PREFIX`
  (`/data/data/com.termux/files/usr`), with no `..` components.
- It is **declared** in the manifest: equal to a `files[].path` or inside a `file_globs[].pattern`.
- `~/.bashrc`, `.profile`, `.bash_profile`, `.zshrc` and `~/.ssh/` are only accepted if the manifest declares
  them as an **exact** path in `files[]` (a glob never covers them).
- There are no special files (devices, fifos).

## What it is NOT

The `SHA256SUMS.txt` **inside** the `.deb` protects against corruption and against a tampered manifest, but not
against someone who builds a package on purpose (changing content and hash together). Authenticity comes from the
hash published **separately** in the Release ([`catalogo-github.en.md`](catalogo-github.en.md)); a local file does not have it, which is why it asks for
confirmation. A signature (minisign/GPG) would be the next improvement: it is not implemented.
