# GitHub catalog: `catalog.json` and `SHA256SUMS.txt`

A separate JSON file on GitHub identifies all the `.deb` packages. Each Release of
`Honkonx/Kairos-Lab` that publishes packages carries, besides the `.deb` files, these assets (generated by
`tools/moduledeb-release.sh`):

| Asset | Purpose |
|---|---|
| `catalog.json` | Identifies all packages in the Release: `module_id`, `version`, `filename`, `size_bytes`, `arch` and **`sha256`** |
| `SHA256SUMS.txt` | The same in `sha256sum` format (`<hash>  <file>`), checkable with `sha256sum -c` |
| `kairos-modules.manifest.json`, `kairos-modules-index.json`, `index.md`, `kairos-modules.tar.xz` (+`.sha256`) | Already existed: tarball manifest and lightweight index |

## `catalog.json` v2

```json
{
  "generated": "2026-10-08T00:00:00Z",
  "schema": 2,
  "repo": "Honkonx/Kairos-Lab",
  "packages": [
    {"module_id": "claude", "version": "2.1.251", "filename": "kairos-module-claude_2.1.251_aarch64.deb",
     "size_bytes": 66962868, "arch": "aarch64", "sha256": "<64 hex>"}
  ]
}
```

The v1 `catalog.json` has no `sha256` and no `schema`.

## How the app uses it

`ModuleDebInstaller.findGithubAsset` walks the Releases, takes the module's most recent `.deb` and, **in the same
Release**, looks for `catalog.json` (or `SHA256SUMS.txt`) to get that file's hash. It downloads to a private
folder, computes the sha256 and compares it; if it does not match, it deletes and aborts. **If the Release does not
publish the hash, it is not installed** (there is no way to verify it).

The hash travels through a different channel than the `.deb` (another Release asset), unlike the internal `.txt`.
It still trusts the repository: a `minisign`/GPG signature with the public key inside the APK would be the next
step (not implemented).

## Publishing

```
bash tools/moduledeb-release.sh [--debs-dir DIR] --release-tag <tag> --upload
```

Generates `catalog.json` and `SHA256SUMS.txt` next to the other files and uploads them with `gh release create/upload`.

## Packages in v1 format

`.deb` packages in v1 format (without an internal `manifest.json` or `SHA256SUMS.txt` and without a hash in the
catalog) are not installed: they must be regenerated with `moduledeb pack` or converted with `moduledeb reseal`,
and the new `catalog.json` published.
